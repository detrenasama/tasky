# AGENTS.md

TUI-приложение «Tasky» на Go: менеджер задач с учётом времени.

План проекта (этапы и их статусы) — в `PLAN.md`; после реализации этапа обновлять его галочки.

## Команды

- `just build` — сборка в `dist/tasky` (`CGO_ENABLED=0`, статическая, версия из `git describe` через `-ldflags -X main.version`)
- `just install` — установка в `~/.local/bin` (`PREFIX=/usr/local just install` — иначе)
- `just release` — сборка linux/amd64+arm64, `tar.gz` + `SHA256SUMS` в `dist/release/`, подсказка публикации через `gh release create`
- `just test` / `just check` — тесты + `go vet` + `gofmt -l`
- `go run .` — запуск приложения (требуется настоящий TTY)
- `go build -o dist/tasky .` — ручная сборка (директория `dist/` создаётся автоматически; `go build ./...` НЕ создаёт файл в каталоге)
- CLI-аргументы: `tasky --version` / `-v` — версия; `tasky upgrade` — самообновление; `tasky help` / `--help` / `-h` — справка (`buildHelpText` в `help.go`); неизвестный аргумент — «неизвестная команда» + справка в stderr, код 1; без аргументов — TUI
- Данные в `~/.local/share/tasky/` (`tasky.db`, `reports/`), переопределение — `TASKY_HOME`

## Структура и стек

- `main.go` — только точка входа: разбор CLI (`--version`/`-v`, `upgrade`), `os.MkdirAll(dataDir)` → `migrateDataDir` (перенос старой `tasky.db` из рабочего каталога при первом запуске, `copyFile`) → `db.Open(<dataDir>/tasky.db)` → чтение имени темы из БД (`db.GetSetting(conn, "theme")`) → `theme.Init(xdg.ConfigDir(), name)` → `ui.New(conn, dataDir, version)` → `tea.NewProgram(..., tea.WithAltScreen())`; каталоги данных/конфига — `internal/xdg` (`DataDir`: `$TASKY_HOME` → `$XDG_DATA_HOME/tasky` → `~/.local/share/tasky`; `ConfigDir`: `$TASKY_CONFIG_HOME` → `$XDG_CONFIG_HOME/tasky` → `~/.config/tasky`); `version.go` — `var version = "dev"` (подстановка `-ldflags`); `upgrade.go` — `runUpgrade()` обёртка над `internal/update`
- `internal/update` — самообновление через GitHub Releases: `Repo = "detrenasama/tasky"`, `apiBase`/`apiBaseURL()` (переопределяется в тестах на httptest и через env `TASKY_API_BASE`); `LatestVersion()` (GET `releases/latest`, `tag_name`), `Compare(a,b)` — семвер `vX.Y.Z` (`TrimV`), `Upgrade(current)` → `upgradeTo(current, exePath)`: скачивание `tasky-<os>-<arch>.tar.gz` + `SHA256SUMS` в temp, проверка суммы (`fetchChecksum`/`fileSHA256`), распаковка `tasky` (`extractTar`) во временный файл рядом с бинарником, `os.Rename` поверх (атомарно; перезапись работающего бинарника на Linux безопасна)
- `internal/ui/app.go` — корневая модель (package ui): переключение экранов (`tasks`/`projects`/`reports`/`settings`), тик 1с (обновление таймеров, «За сегодня» и недельной суммы на tasks-экране), `tea.WindowSizeMsg`, выход по `q`/`ctrl+c`; при запущенной сессии выход сначала показывает предупреждение (`m.quitting` + `m.quitTitle` из `RunningSession`): Enter останавливает сессию (`StopSession`) и выходит, Esc/q отменяют; аналогично переход на отчёты клавишей `r` при запущенной сессии — предупреждение `m.reportConfirm` + `m.reportTitle` («Остановить и сформировать отчёт?»: Enter — `StopSession` + `switchScreen(screenReports)`, Esc/n/r/q/ctrl+c — отмена); диалоги рендерятся в `View()` поверх всех модалок (сначала `quitting`, затем `reportConfirm`); здесь же фиксированная хрома: `View()` = вкладки (1 строка, `tabsLine` — текущая страница accent, остальные dim) + шапка (1 строка) + средняя область (`h-3`) + подвал (подсказки клавиш); если открыта модалка — поверх всей хромы `overlay()` из `internal/ui/modal.go`; на экране отчётов `ctrl+s` сохраняет отчёт в файл (перехват ДО глобального переключения вкладок); `s` на отчётах — обычное переключение на «Настройки»; `modalOpen()` учитывает и `settings.mode`; конструктор `New(conn, dataDir, version)` создаёт экраны и общий `reportConfig` (дефолт `saveDir = <dataDir>/reports`); стартовая проверка обновления: `Init()` запускает `checkUpdateCmd()` (горутина с `update.LatestVersion`, ошибка сети молча игнорируется), `updateMsg` сравнивает версии (`update.Compare`) и кладёт результат в `m.updateVer`/`m.tasks.updateVer`

## Нюансы

- ВАЖНО: рабочая база в `~/.local/share/tasky/tasky.db` — БОЕВАЯ, с реальными данными. Никогда не запускать приложение и тесты без `TASKY_HOME`, указывающего на изолированный каталог (например `/tmp/opencode/smoke/data`), и никогда — из каталога, где лежит `tasky.db` (устаревшая копия в корне репозитория тоже неприкосновенна): `migrateDataDir` скопирует её при первом запуске. Все запуски/смоук — строго `TASKY_HOME=/tmp/...`.
- SQLite открывается через DSN с прагмами `foreign_keys(1)` и `busy_timeout(5000)` (см. `db.go`) — не отключать: без FK каскады не работают.
- Активная сессия учёта времени — это запись `time_entries` с `ended_at IS NULL`; не более одной на подзадачу (unique partial index), а `StartSession` в транзакции останавливает любую другую активную сессию — одновременно идёт максимум одна подзадача.
- Недельная сумма (`WeeklyTotal` в `time.go`) и «За сегодня» (`TodayTotal`): общий `rangeTotal(conn, from, to, now)` — записи, пересекающие интервал, обрезаются по границам; неделя с понедельника 00:00 локального времени; активная сессия учитывается частично (до текущего момента).
- Отчёт (`ReportEntries` в `reports.go`): только завершённые записи (`ended_at`), обрезка по границам интервала как в `rangeTotal`, `HAVING secs > 0` (подзадачи с нулевым временем скрываются), `ORDER BY t.created_at, t.id, s.sort_order, s.id` (порядок по созданию, не по времени); `projectID=0` — все проекты; `?` — позиционные параметры, именованные `?name` в SQLite не работают; `ReportByTask(entries)` группирует в задачи с подзадачами; `JournalEntriesByRange(conn, from, to)` — записи журнала за период (для отчёта с журналом).
- `padLines` клампит `w`/`h` (0/отрицательные) — при старте BubbleTea вызывает `View()` с размером 0×0 до первого `WindowSizeMsg`, и ветка с данными в `view()` иначе паникует на `lines[:h]`.
- Экраны — указатели (`*tasksScreen`): описания элементов подзадач читают `now` через замыкание на экран, поэтому без указателя обновления таймера не будут видны.
- ID задач и подзадач — отдельные последовательности и могут совпадать: поиск/выделение по ID всегда по паре `(kind, id)` (`selectedKindID`/`indexByKindID`/`selectByKindID` в `internal/ui/tasks_screen.go`), иначе курсор попадает в чужой элемент.
- `list.Select(0)` на пустом списке ставит `Index()=0` при `len(items)==0` — перед `Select` и индексацией по выбранному элементу всегда проверять длину (`canDelete()` в `internal/ui/tasks_screen.go`).
- Тестировать TUI в неинтерактивной оболочке нельзя (`/dev/tty` недоступен). Минимальная проверка: `printf 'q' | timeout 10 script -qec "stty rows 30 cols 100; ./tasky" /dev/null` — код 0. При прогоне клавиатурных сценариев: `(sleep 0.6; printf 'n'; ...; printf 'q') | timeout N script -qec "stty rows 30 cols 100; ./tasky" /dev/null`; паузы ≥0.3с между клавишами (ранние нажатия теряются до инициализации TUI); Enter посылать как `\r`, не `\n` (в raw-режиме `\n` — это ctrl+j!), Ctrl+S — как `\023` (НЕ `\030` — это ctrl+x!), Tab — `\t`, стрелка вниз — `\033[B`; `stty rows 30 cols 100` обязателен — без него pty имеет размер 0x0 и ломает рендер. ВАЖНО: для сценариев с колонкой описания задач нужно `cols 150` (descW появляется только при `w≥110`). Смоук-прогоны — из `/tmp/opencode/smoke/` (копия бинаря из `dist/` (`cp dist/tasky /tmp/opencode/smoke/`), своя tasky.db, свободно пересоздавать): сначала прогон `printf 'q' | ... ./tasky` для схемы, затем сид через python3 (колонки таблиц смотреть в `schema.go`: `description`, не `desc`; `created_at`, у tasks ещё `completed_at`).

- Режим приложения только альтернативный экран (WithAltScreen).
