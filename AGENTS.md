# AGENTS.md

TUI-приложение «Tasky» на Go: менеджер задач с учётом времени.

План проекта (этапы и их статусы) — в `PLAN.md`; после реализации этапа обновлять его галочки.

## Команды

- `go run .` — запуск приложения (требуется настоящий TTY)
- `go build -o dist/tasky .` — сборка бинарника в `dist/` (директория создаётся автоматически; заметь: `go build ./...` НЕ создаёт файл в каталоге)
- `go vet ./...` и `gofmt -l .` — проверки перед завершением задачи
- `go test ./...` — тесты (internal/ui/*_test.go, internal/db/*_test.go)

## Структура и стек

- `main.go` — только точка входа: `db.Open(dbPath)` → `ui.New(conn)` → `tea.NewProgram(..., tea.WithAltScreen())`; вся программа в `internal/ui`
- `internal/ui/app.go` — корневая модель (package ui): переключение экранов (`tasks`/`projects`/`reports`/`settings`), тик 1с (обновление таймеров, «За сегодня» и недельной суммы на tasks-экране), `tea.WindowSizeMsg`, выход по `q`/`ctrl+c`; при запущенной сессии выход сначала показывает предупреждение (`m.quitting` + `m.quitTitle` из `RunningSession`): Enter останавливает сессию (`StopSession`) и выходит, Esc/q отменяют; аналогично переход на отчёты клавишей `r` при запущенной сессии — предупреждение `m.reportConfirm` + `m.reportTitle` («Остановить и сформировать отчёт?»: Enter — `StopSession` + `switchScreen(screenReports)`, Esc/n/r/q/ctrl+c — отмена); диалоги рендерятся в `View()` поверх всех модалок (сначала `quitting`, затем `reportConfirm`); здесь же фиксированная хрома: `View()` = вкладки (1 строка, `tabsLine` — текущая страница accent, остальные dim) + шапка (1 строка) + средняя область (`h-3`) + подвал (подсказки клавиш); если открыта модалка — поверх всей хромы `overlay()` из `internal/ui/modal.go`; на экране отчётов `ctrl+s` сохраняет отчёт в файл (перехват ДО глобального переключения вкладок); `s` на отчётах — обычное переключение на «Настройки»; `modalOpen()` учитывает и `settings.mode`; конструктор `New(conn)` создаёт экраны и общий `reportConfig`
- `internal/ui/tasks_screen.go` — главный экран: три колонки в средней области на всю ширину (пороги: `w≥110` — list|описание|info в пропорции 2:2:1, `70≤w<110` — list+info (2:1), `w<70` — только list; математика в `resize()`); список с раскрывающимися подзадачами (`enter`/`→`, `▸`/`▾`, подзадачи с `├`); статусы задач/подзадач из каталога `statuses`: строка статуса цветная (Foreground по `color`), слева полоса `statusBar` (2 пробела Background), в фокусе списка `x` — следующий по быстрой цепочке (`quickStatuses`), `z` — предыдущий, `c` — модалка выбора из всех статусов (преселект на текущем); переходы и задач, и подзадач пишутся в `status_history` (последние 6 — в info-панели «История статусов:», штамп `2006-01-02 15:04` отдельной строкой, `wrapText`; частые переходы сливаются: если от последней записи владельца прошло ≤60с (`statusMergeWindow` в statuses.go), запись заменяется — обновляются `to_status`/`note`/`created_at`, `from_status` остаётся статусом начала группы; возврат к этому `from_status` в окне слияния удаляет запись (нет «Новая → Новая»); иначе добавляется новая запись; смена статуса на тот же с другим комментарием (статусы с `note_prompt`) тоже пишется — в окне слияния заменяет запись, после окна добавляет «X → X (комментарий)», повторный ввод того же комментария запись не создаёт; для подзадачи история показывается ниже записей времени; `historyLines()`), журнал подзадачи содержит только ручные записи (Ctrl+J); выбор статуса без `note_prompt` в модалке `c` применяет его и закрывает модалку; статус с `note_prompt` требует заметку (модалка taskStatusNote, Ctrl+S применить, Esc отменить); info-панель: для подзадачи — статус + список time entries (`TimeEntriesBySubtask`) + история статусов, для задачи — статус + подзадачи со временем + история статусов; внизу «Общее» (высота по контенту) — «За сегодня» (`s.today`), недельная сумма (`s.weekly`) и текущая запущенная подзадача (`s.run` из `RunningSession`); верхняя часть info-колонки растягивается на оставшуюся высоту; колонка «Описание»: для задачи — заголовок + `wrapText` описания + блок «Ссылки:» (как в проектах), для подзадачи — блок «Описание» (1/3 высоты) + линия-разделитель + блок «Журнал» (2/3): записи хронологически (старые сверху) с dim-штампом `02.01.2006 15:04` и текстом `wrapText`; пустой журнал — подсказка «Ctrl+J — добавить»; `focus` (taskFocusList/taskFocusDesc), `Tab` переключает колонку (при `descW>0`); в фокусе списка: `n`/`a` — новые задача/подзадача, `d` — удаление, `ctrl+l` — старт/пауза, `[`/`]` — проект, смена выделения → `loadInfo()`+`loadDesc()`+`GotoTop()`; после создания задачи/подзадачи — `selectByKindID` + те же три вызова; в фокусе описания: ↑/↓/PgUp/PgDn — скролл `descV`, `e` — инлайн-редактирование описания (НЕ модалка, как projDescEdit: textarea вместо колонки, Ctrl+S сохранить, Esc — отмена), `l` — модалка ссылки (два textinput'а: название → адрес, как в проектах), `o` — список ссылок (Enter — `openURL`, `d` — удалить с подтверждением taskLinkConfirm), `ctrl+j` — модалка записи журнала (textarea высотой 10 строк, Ctrl+S сохранить, Esc — отмена; после сохранения `descV.GotoBottom()` — новая запись внизу), `j` — редактировать самую свежую запись ТЕКУЩЕГО дня (`sameDay(e.CreatedAt, s.now)`; если сегодняшних записей нет — `lastErr` «редактировать можно только записи текущего дня»); поиск: `/` открывает модалку taskSearch с textinput (живой фильтр по мере ввода: Enter применяет запрос и закрывает модалку, Esc отменяет, Esc в обычном режиме при активном поиске сбрасывает его); регистронезависимый поиск по текущему проекту — названия и описания задач/подзадач (поля `Description` в `db.Task`/`db.SubtaskWithTime`, подгружаются запросами) и текст записей журнала подзадач (карта `s.journalTexts` из `db.JournalTexts`, обновляется в `loadData`); `buildItems()` при непустом `searchQuery` строит дерево через `buildSearchItems(q)`/`subMatches`: совпавшая задача — со всеми подзадачами, совпавшая подзадача — только она (задача раскрыта, остальные скрыты), несовпавшие задачи исключены; при пустом поиске `buildItems()` пропускает скрытые задачи — `hiddenDue(t)` (тип статуса `done` && `completed_at` старше `hideDays`×24ч; порог из БД, `loadHideDays`, по умолчанию 7, 0 — выкл); поиск фильтр не применяет (скрытые находятся через `/`), подзадачи и отчёты не фильтруются; при активном поиске шапка «поиск: запрос», подвал «Поиск: "…" — / — изменить · Esc — сбросить», пустой результат — `fixedBox` «Ничего не найдено»; встроенный фильтр bubbles/list отключён (`SetFilteringEnabled(false)` — его `/` ломали перехватываемые экраном клавиши n/a/d/x/z/c); `ctrl+j`/`j` работают только при выбранной подзадаче; модалки: taskInput, taskConfirm, taskLinkInput, taskLinks, taskLinkConfirm, taskJournal (taskJournal также используется для редактирования записи — признак `journalEditID != 0`), taskStatusPick, taskStatusNote — маршрутизируются в `updateTasks` из `internal/ui/app.go` (методы `header`/`footer`/`view`/`dialog`)
- `internal/ui/projects_screen.go` — экран проектов: три колонки `w≥110` — list|описание|сводка 1:3:1 (`u=(w-4)/5`, list += остаток), `60≤w<110` — list+описание (1:1), `w<60` — только list; `focus` (projFocusList/projFocusDesc), `Tab` переключает колонку (при `descW>0`), активная — `focusBox`, неактивная — `dimBox`; длинные обрезаются многоточием); в модалке списка у `linkItem` Title = название (или URL), Description = URL (только если название есть); правая (`infoBox`) — dim-заглушка «Сводка и настройки»; поиск как на задачах: `/` — модалка projSearch (живой фильтр по мере ввода: Enter применяет и закрывает, Esc отменяет; Enter повторно при открытой модалке префиллит прошлый запрос), ищет по названию, описанию и ссылкам проекта (карта `s.linkTexts` из `db.ProjectLinksTexts`, `db.Projects` уже отдаёт `Desc`); `buildItems()` при непустом `searchQuery` фильтрует `s.projects` (выбор сохраняется по ID), `selectedProjectID()` берёт выбранный элемент списка (не индекс в `s.projects` — при фильтре индексы не совпадают); при активном поиске шапка «поиск: запрос», подвал «Поиск: "…" — / — изменить · Esc — сбросить», пустой результат — `fixedBox` «Ничего не найдено»; Esc при активном поиске перехватывается в `internal/ui/app.go` ДО глобального esc «назад на задачи» (`clearSearch()`); модалки: projInput, projConfirm, projLinkInput, projLinks, projLinkConfirm — маршрутизируются в `updateProjects` из `internal/ui/app.go`
- `internal/ui/reports_screen.go` — страница «Отчеты» (этап 2: периоды + сохранение): фикс-шапка `topBox` с периодом (`periodLabel`: сегодня/вчера/неделя/месяц — названия месяцев в `monthNames`, свой период — «Отчет · даты» или «Отчет за день · дата») и «Общее время:», под ней строка статуса сохранения (`statusLine`: зелёное «Отчёт сохранён: путь» или красная ошибка), ниже скроллируемый viewport `repV` (↑/↓/PgUp/PgDn) со строками «Задача · время» и «  ├ Подзадача · время» (`fmtDur`), при `includeJournal` под подзадачей dim-строки «[ДД.ММ ЧЧ:ММ] текст» из `s.journal` (map подзадача → записи); пустой период — «Времени за период ещё не учтено.»; данные статичны (только завершённые записи, тик не нужен): `load()` вызывается из `switchScreen` в internal/ui/app.go и при старте; `cfg *reportConfig{period, projectID, includeJournal, saveDir, customFrom, customTo}` — ОБЩИЙ указатель с settings-экраном (свой период хранится готовыми границами, `customFrom` 00:00, `customTo` исключая конец); `periodRange()` — [00:00,+24h)/вчера/неделя с понедельника/месяц/свой; `save()` по клавише `ctrl+s` (из internal/ui/app.go) — `os.MkdirAll(cfg.saveDir)` (пустой → «reports»), файл `saveFileName()`: одиночный день — `2006-01-02.txt`, неделя/свой диапазон — `даты_через_подчёркивание.txt`, месяц — `2006-01.txt`; `resize(w,h)` → `repV.Width = w-4`, высота пересчитывается в `view()` под статус-строку; `esc` на любой не-tasks странице возвращает к задачам (обработка в `internal/ui/app.go`)

- UI: `bubbletea` + `bubbles` (list, textinput, textarea, viewport) + `lipgloss`; запуск через `tea.NewProgram(..., tea.WithAltScreen())`
- Списки (`bubbles/list` v1.0.0): делегат — `list.NewDefaultDelegate()`, описание элемента — методы `Title()`/`Description()` интерфейса `DefaultItem` (старого `SetDescriptionFunc` нет); ВАЖНО: `View()` НЕ дополняет строки до `SetWidth` — ряды рендерятся по контенту, паддинг вручную через `padLines` (см. `view()` в tasks_screen); хром `boxStyle` = 4 (бордер 2 + паддинг 2) — контент рамки паддится до `w-4`; клавиша `Quit` в keymap по умолчанию = `q` И `esc` — `list.Update(esc)` вернёт `tea.Quit` и приложение выйдет: для списков внутри модалок обязателен `DisableQuitKeybindings()` (см. `linkList` в projects_screen и tasks_screen), иначе Esc закроет приложение

## Нюансы

- SQLite открывается через DSN с прагмами `foreign_keys(1)` и `busy_timeout(5000)` (см. `db.go`) — не отключать: без FK каскады не работают.
- Активная сессия учёта времени — это запись `time_entries` с `ended_at IS NULL`; не более одной на подзадачу (unique partial index), а `StartSession` в транзакции останавливает любую другую активную сессию — одновременно идёт максимум одна подзадача.
- Недельная сумма (`WeeklyTotal` в `time.go`) и «За сегодня» (`TodayTotal`): общий `rangeTotal(conn, from, to, now)` — записи, пересекающие интервал, обрезаются по границам; неделя с понедельника 00:00 локального времени; активная сессия учитывается частично (до текущего момента).
- Отчёт (`ReportEntries` в `reports.go`): только завершённые записи (`ended_at`), обрезка по границам интервала как в `rangeTotal`, `HAVING secs > 0` (подзадачи с нулевым временем скрываются), `ORDER BY t.created_at, t.id, s.sort_order, s.id` (порядок по созданию, не по времени); `projectID=0` — все проекты; `?` — позиционные параметры, именованные `?name` в SQLite не работают; `ReportByTask(entries)` группирует в задачи с подзадачами; `JournalEntriesByRange(conn, from, to)` — записи журнала за период (для отчёта с журналом).
- `padLines` клампит `w`/`h` (0/отрицательные) — при старте BubbleTea вызывает `View()` с размером 0×0 до первого `WindowSizeMsg`, и ветка с данными в `view()` иначе паникует на `lines[:h]`.
- Экраны — указатели (`*tasksScreen`): описания элементов подзадач читают `now` через замыкание на экран, поэтому без указателя обновления таймера не будут видны.
- ID задач и подзадач — отдельные последовательности и могут совпадать: поиск/выделение по ID всегда по паре `(kind, id)` (`selectedKindID`/`indexByKindID`/`selectByKindID` в `internal/ui/tasks_screen.go`), иначе курсор попадает в чужой элемент.
- `list.Select(0)` на пустом списке ставит `Index()=0` при `len(items)==0` — перед `Select` и индексацией по выбранному элементу всегда проверять длину (`canDelete()` в `internal/ui/tasks_screen.go`).
- Тестировать TUI в неинтерактивной оболочке нельзя (`/dev/tty` недоступен). Минимальная проверка: `printf 'q' | timeout 10 script -qec "stty rows 30 cols 100; ./tasky" /dev/null` — код 0. При прогоне клавиатурных сценариев: `(sleep 0.6; printf 'n'; ...; printf 'q') | timeout N script -qec "stty rows 30 cols 100; ./tasky" /dev/null`; паузы ≥0.3с между клавишами (ранние нажатия теряются до инициализации TUI); Enter посылать как `\r`, не `\n` (в raw-режиме `\n` — это ctrl+j!), Ctrl+S — как `\023` (НЕ `\030` — это ctrl+x!), Tab — `\t`, стрелка вниз — `\033[B`; `stty rows 30 cols 100` обязателен — без него pty имеет размер 0x0 и ломает рендер. ВАЖНО: для сценариев с колонкой описания задач нужно `cols 150` (descW появляется только при `w≥110`).
