## Этап 1. Отчёт «за сегодня» — [x] завершён

Экран «Отчеты» в приложении. Собирает только завершённые записи времени за сегодня, группирует по задачам и подзадачам (порядок по созданию, а не по времени), показывает «Общее время». При переходе на отчёты клавишей `r` во время запущенной сессии учёта времени показывается подтверждение «Остановить и сформировать отчёт?». Пустой день — «Времени за период ещё не учтено.».

Реализация: `internal/db/reports.go` (`ReportEntries`, `ReportByTask`), `reports_screen.go`, тесты в `reports_test.go` и `ui_test.go`.

## Этап 2. Периоды, журнал, сохранение, настройки — [x] завершён

Периоды отчёта: сегодня, вчера, неделя (с понедельника), месяц, свой диапазон. Свой период задаётся как `ДД.ММ.ГГГГ` или `01.08.2026-03.08.2026` (разделители `-`/`–`/`—`, ведущие нули необязательны), ошибка формата — красная строка в модалке. Опционально в отчёт включаются записи журнала. Сохранение отчёта — `ctrl+s` в файл (день — `2006-01-02.txt`, диапазон — через подчёркивание, месяц — `2006-01.txt`), каталог задаётся в настройках (по умолчанию `reports/`). Экран «Настройки»: строки Период/Проект/Журнал/Каталог, Enter открывает модалку изменения. Настройки отчёта — общий объект `reportConfig` для экранов отчётов и настроек.

## Этап 2.1. Модалки выбора периода и проекта — [x] завершён

Модалки со списками периодов и проектов переведены на собственный компонент `pickList` (bubbles/list отброшен: его постраничный вывод не подходил). Плотный список без пустых строк между элементами, курсор `▸`, преселект на текущем значении, до 12 видимых вариантов, при переполнении — плавный скролл за курсором (без пагинации). Движение: ↑/↓/PgUp/PgDn, Enter — выбрать, Esc — отмена.

## Этап 4. Настройка статусов задач и подзадач — [x] завершён (включая этап 5)

Каталог статусов (8 по умолчанию) хранится в БД (`statuses`) и редактируется в разделе «Статусы» экрана «Настройки»: создание/удаление/изменение имени, типа (`new`/`in_progress`/`done`), цвета и флажка «быстрая цепочка». Типы статусов задают поведение: `done` — проставление/очистка `completed_at` (нужно для этапа 6), `new` — первый такой статус является статусом по умолчанию при создании.

Статусы по умолчанию: Новая `#6a9955`, Ожидает подтверждения `#4f7942`, В работе `#569cd6`, На проверке `#c586c0`, Ожидает ответа `#d7ba7d`, Делегирована `#ce9178`, Выполнена `#8a8a8a`, Отменена `#8f3e3e`; палитра для выбора — 10 цветов (добавлены `#4ec9b0`, `#d47a9e`). Быстрая цепочка: Новая → В работе → На проверке → Выполнена, без зацикливания (x на «Выполнена» ничего не делает, z на «Новой» тоже); вне цепочки x → первый её элемент, z → последний. Клавиши на экране задач: `x` — следующий по цепочке, `z` — предыдущий, `c` — модалка выбора из всего списка (преселект на текущем статусе).

Переходы задач и подзадач пишутся в `status_history` (последние 6 — в info-панели «История статусов:» для обеих сущностей); переход в течение ≤60с от последней записи владельца заменяет её (`to_status`/`note`/`created_at` обновляются, `from_status` остаётся), возврат к `from_status` в этом окне удаляет запись (нет «X → X»), иначе добавляется новая запись; смена статуса на тот же с другим комментарием пишется (в окне — замена, после — «X → X (комментарий)»), повторный тот же комментарий записи не создаёт. Ручной журнал подзадач (Ctrl+J) содержит только свои записи. Статусы с подсказкой `note_prompt` («Делегирована» — «Имя коллеги:», «Отменена» — «Причина отмены:») требуют заметку — модалка ввода, Ctrl+S применить, Esc отменить. Удаление статуса, используемого задачами/подзадачами, запрещено (ошибка в модалке). Миграция: старые `todo`/`in_progress`/`done` маппятся на «Новая»/«В работе»/«Выполнена» (таблицы пересоздаются без CHECK на status), старые записи «Статус: X → Y» из журнала подзадач переносятся в `status_history`.

Реализация: `internal/db/statuses.go`, `schema.go` (таблицы `statuses`, `status_history`, `migrateStatuses`), `tasks_screen.go` (x/z/c, цвета, история), `settings_screen.go` (раздел «Статусы»), тесты в `internal/db/statuses_test.go` и `ui_test.go`.

## Этап 6. Скрытие завершённых задач (N дней) — [x] завершён

Задачи с завершённым статусом (тип `done`), у которых `completed_at` старше N дней (24×N часов), скрываются из списка задач. Порог N — строка «Скрытие» на странице настроек (модалка ввода целого ≥ 0), по умолчанию 7; 0 — скрытие выключено. Значение хранится в БД (таблица `settings`, ключ `hide_days`) и переживает перезапуск — первая персистентная настройка приложения.

Фильтр применяется на уровне UI в `buildItems()` (задачи не попадают в список): скрытая задача остаётся в данных, поэтому полнотекстовый поиск (`/`) её находит, а смена статуса из `done` (очистка `completed_at`) сразу возвращает её в список. Скриваются только задачи: подзадачи и отчёты не фильтруются (отчёты — исторические данные). Пересборка списка происходит при `loadData()` — при переключении экрана, смене проекта/статуса/поиска.

Реализация: `internal/db/settings.go` (`GetSetting`/`SetSetting`), таблица `settings` в `schema.go`, `loadHideDays`/`parseHideDays`/модалка `settingsHideInput` в `settings_screen.go`, `hiddenDue` в `tasks_screen.go`, тесты в `internal/db/settings_test.go`, `settings_test.go` и `tasks_test.go` (`TestHideCompletedTasks`).

## Этап 7. Теги задач — [x] завершён

Несколько тегов на задачу — пометка номеров задач внешних сервисов (Jira, трекер компании и т.п.). На экране задач клавиша `g` (фокус списка и описания; для подзадачи — теги родительской задачи) открывает модалку тегов: список на `pickList` с цветными метками `[текст]` (цвет от типа, при URL — подчёркнуто), `n` — новый, Enter — редактировать, `d` — удаление с подтверждением. Форма тега: **Тип** (модалка выбора из каталога, Enter), **Значение** (обязательное), **URL** (опционально); Ctrl+S — сохранить, Esc — отмена.

Типы тегов — настраиваемый каталог (таблица `tag_types`) в разделе «Типы тегов» настроек (7-я строка): имя + тип (`text`/`task_id`) + цвет (общая палитра). По умолчанию сидятся два типа: **Jira** (`task_id`, синий) и **Трекер** (`task_id`, зелёный) — цвет привязан к типу, поэтому консистентность «джира одного цвета, трекер другого» автоматическая. Удаление используемого типа запрещено (`ErrTagTypeInUse`). Теги хранятся в `task_tags` (task_id → type_id, значение, URL), цвет денормализуется из типа.

Отображение: цветные `[тег]` в строке названия задачи (список; на узких колонках обрезаются делегатом — полный набор в модалке и info-панели), блок «Теги:» в info-панели выбранной задачи, в отчётах — метки в строке задачи и в сохраняемом файле (номера внешних сервисов, база для этапа 8). Полнотекстовый поиск `/` находит задачи и по тексту тегов.

Реализация: `internal/db/tags.go`, `schema.go` (таблицы `tag_types`/`task_tags`, `seedTagTypes`), `tasks_screen.go` (клавиша g, модалки taskTags/taskTagEdit/taskTagTypePick/taskTagConfirm, метки, поиск), `settings_screen.go` (раздел «Типы тегов»), `reports_screen.go` (теги в строках и файле), тесты в `internal/db/tags_test.go` и `internal/ui/tags_test.go`.

## Этап 9. Полнотекстовый поиск задач/подзадач — [x] завершён

Клавиша `/` на экране задач открывает модалку поиска, фильтр применяется по мере ввода (живой). Регистронезависимо ищет по названию и описанию задач и подзадач, а также по тексту записей журнала подзадач текущего проекта. Совпавшая задача показывается со всеми своими подзадачами, совпавшая подзадача — только она (задача раскрыта, несовпавшие подзадачи скрыты). Enter применяет запрос и закрывает модалку (фильтр остаётся), Esc отменяет (фильтр сбрасывается); Esc в обычном режиме при активном поиске тоже сбрасывает. При активном поиске: шапка «поиск: запрос», подвал «Поиск: "…" — / — изменить · Esc — сбросить», пустой результат — «Ничего не найдено по запросу». Встроенный фильтр bubbles/list отключён (`SetFilteringEnabled(false)`): его `/` ломали перехватываемые экраном клавиши n/a/d/x/z/c.

На экране проектов — то же самое: `/` ищет по названию, описанию и ссылкам проектов; Esc при активном поиске перехватывается в `main.go` до глобального esc «назад на задачи» (`clearSearch()`).

Реализация: `tasks_screen.go` (режим `taskSearch`, `buildSearchItems`/`subMatches`), `projects_screen.go` (режим `projSearch`, `buildItems`), `internal/db/tasks.go` (`JournalTexts`, описание в `TasksByProject`/`SubtasksByProject`/`SubtasksWithTime`), `internal/db/projects.go` (`ProjectLinksTexts`), тесты в `ui_test.go` (`TestTaskSearch`, `TestProjectSearch`) и `tasks_test.go`/`projects_test.go`.

## Этап 10. Установка и обновления — [x] завершён

Модуль переименован в `github.com/detrenasama/tasky` (совпадает с репозиторием для `go install`). Добавлены `LICENSE` (MIT) и `README.md`. Сборка через `Justfile`: статическая (`CGO_ENABLED=0`), версия подставляется `-ldflags -X main.version=$(git describe --tags)`, `just release` собирает linux/amd64+arm64 в `dist/release/` (tar.gz + SHA256SUMS) и печатает команду публикации `gh release create`.

Данные переехали в XDG: `~/.local/share/tasky/` (`tasky.db`, отчёты по умолчанию `reports/`), переопределение — `TASKY_HOME` (`internal/xdg`); при первом запуске новой версии старая база из рабочего каталога переносится (`migrateDataDir`).

Самообновление (`internal/update`, CLI `tasky upgrade`): сравнение версий (семвер, `Compare`/`TrimV`), скачивание `tasky-<os>-<arch>.tar.gz` + `SHA256SUMS` из последнего релиза GitHub, проверка контрольной суммы, атомарная замена бинарника (`os.Rename`). При старте TUI фоновая проверка (`checkUpdateCmd`) показывает в шапке задач «обновление: vX.Y.Z — tasky upgrade». Установка: `scripts/install.sh` (curl + SHA256) в `~/.local/bin`, `just install`, `go install`.

Реализация: `version.go`, `upgrade.go`, `help.go`, `internal/xdg`, `internal/update` (+ тесты на httptest-сервере), изменения `main.go`/`internal/ui/app.go`/`tasks_screen.go`, `Justfile`, `scripts/install.sh`, `LICENSE`, `README.md`.

## Этап 11. Темы и плоский интерфейс — [x] завершён

Интерфейс переведён с рамок на плоские панели в духе OpenCode TUI: колонки задач/проектов — заливка фоном без рамок, у фокусированной панели — акцентная полоса слева, остальная хрома (вкладки, подвал) — цветами. `fixedBox`/`padLines` вычисляют размеры из фрейма стиля (`GetHorizontalFrameSize`/`GetVerticalFrameSize`), модалки — `ModalStyle` (фон + лёгкая рамка), подложка затемняется через `Dim` (faint-цвет, цвета статусов сохраняются).

Темы — JSON-каталог в `internal/ui/theme/` с 5 встроенными: `opencode` (по умолчанию), `classic` (прежний вид), `nord`, `dracula`, `one-dark`. Пользовательские темы — `~/.config/tasky/themes/*.json` (переопределение каталога — `TASKY_CONFIG_HOME`), все цвета опциональны, недостающие падают на дефолт opencode. Активная тема хранится в БД (`settings.theme`) и переживает перезапуск; окружение `TASKY_THEME` переопределяет её. Переключение — строка «Тема» на странице «Настройки» (модалка со списком на `pickList`, Enter применяет и сохраняет).

Реализация: `internal/ui/theme` (`theme.go` — стили от активной темы, `Pane`, `ApplyToDelegate`, `Faint`/`Muted`/`Dim`, `ModalStyle`; `themes.go` — парсинг JSON, `//go:embed themes/*.json`, `Init`/`Apply`/`Themes`/`ActiveName`/`ThemesDir`; `theme_test.go`), `internal/xdg` (`ConfigDir`), плоские панели и `retheme` во всех экранах, `main.go` (`theme.Init` до `ui.New`), `settings_screen.go` (режим `settingsThemeList`), `README.md`.
