# Tasky

TUI-менеджер задач с учётом времени на Go (Bubble Tea + gRPC + SQLite).

Задачи и подзадачи в проектах, настраиваемые статусы с быстрой сменой по цепочке, теги внешних сервисов, учёт времени по подзадачам и отчёты за период с сохранением в файл.

## Возможности

- Проекты, задачи, подзадачи; полнотекстовый поиск (`/`)
- Каталог статусов с цветами и быстрой цепочкой (`x`/`z`), история переходов
- Теги задач (Jira, трекеры — тип, значение, URL)
- Учёт времени (`ctrl+l` старт/пауза), отчёты за день/неделю/месяц/свой период
- Скрытие давно завершённых задач, записи журнала подзадач
- Клиент-серверная архитектура: интерфейс общается с данными по gRPC через локальный unix-сокет

## Установка

Требуется Linux (amd64).

**Готовым бинарником** — скрипт качает последний релиз с GitHub, проверяет SHA256 и ставит в `~/.local/bin`:

```sh
curl -sSL https://raw.githubusercontent.com/detrenasama/tasky/main/scripts/install.sh | sh
```

**Из исходников** (нужен Go и `just`):

```sh
just build
just install        # в ~/.local/bin
```

**Через go install** (нужен Go):

```sh
go install github.com/detrenasama/tasky@latest
```

## Обновление

```sh
tasky upgrade
```

Команда проверяет последний релиз на GitHub, скачивает, проверяет контрольную сумму и атомарно заменяет бинарник. О наличии новой версии приложение также сообщает в подвале экрана задач.

Версия: `tasky --version`. Справка по командам: `tasky help`.

## Сервер и клиент

`tasky` запускает интерфейс и локальный gRPC-сервер данных: если сервер уже работает — интерфейс подключается к нему, иначе сервер поднимается на время работы и останавливается при выходе. Для работы сервера отдельно от интерфейса:

```sh
tasky serve       # сервер в foreground (Ctrl+C — остановить)
tasky attach      # интерфейс, подключённый к запущенному серверу
tasky status      # JSON: время за сегодня и запущенная подзадача (для индикаторов)
```

`tasky status` печатает `{"today_seconds":N,"subtask":{"id":I,"title":"..."}}` (без запущенной подзадачи — `"subtask":null`) и выходит с кодом 1, если сервер не запущен. На нём работает GNOME-индикатор [tasky-gnome-indicator](https://github.com/detrenasama/tasky-gnome-indicator).

Основной API — gRPC (унарные RPC 1:1 с методами хранилища). Для внешних интеграций сервер дополнительно слушает HTTP: `GET /status` отдаёт тот же JSON, что и `tasky status`. Адрес по умолчанию — `http://127.0.0.1:9110`, переопределяется `--http-addr ADDR` или `TASKY_HTTP_ADDR`:

```sh
curl http://127.0.0.1:9110/status
```

Все процессы одного каталога данных делят одну базу: данные видны из любого клиента. Сокет по умолчанию — `<каталог данных>/tasky.sock`, переопределяется `--socket PATH` или `TASKY_SOCKET`.

## Веб-интерфейс

Кроме терминального TUI есть веб-интерфейс с тем же функционалом, но с
кнопками и контекстными меню — для тех, кто не работает в терминале. Это
второй клиент тех же данных: он общается с сервером по HTTP/JSON (эндпоинты
`/api/*`), а не по gRPC. Один и тот же бинарник отдаёт и TUI-сервер, и веб.

Запуск — как обычно:

```sh
tasky            # поднимает сервер и сразу отдаёт веб по HTTP
tasky serve      # только сервер; веб доступен на http://127.0.0.1:9110
```

Откройте в браузере **http://127.0.0.1:9110** — там веб-интерфейс
(Проекты / Задачи / Отчёты / Настройки). Никакой авторизации нет: сервер
слушает только `127.0.0.1`, рассчитан на локальный запуск на машине
пользователя.

Фронтенд собирается в `web/` (React + TypeScript + Vite) и встраивается в
бинарник через `//go:embed` (каталог `web/dist`):

```sh
just web-build   # собрать фронтенд (web/dist)
just build       # собрать бинарник вместе с фронтендом
just web-dev     # локальная разработка: go run . serve + Vite dev (HMR, прокси /api)
```

Если фронтенд не собран, по адресу отдаётся заглушка с подсказкой.

## Данные

## Данные

База и отчёты хранятся в `~/.local/share/tasky/` (`tasky.db`, `reports/`). Каталог можно переопределить переменной окружения `TASKY_HOME` — например, для изолированного запуска:

```sh
TASKY_HOME=/tmp/tasky-dev tasky
```

Отчёты также можно сохранять в произвольный каталог из настроек приложения.

## Темы

Плоский интерфейс с цветовыми темами (по умолчанию `opencode`). Встроенные темы: `opencode`, `classic` (прежний вид), `nord`, `dracula`, `one-dark`. Смена — страница «Настройки» → строка «Тема».

Своя тема — JSON-файл в `~/.config/tasky/themes/` (каталог переопределяется `TASKY_CONFIG_HOME`):

```json
{
  "name": "my",
  "colors": {
    "accent": "#5c9cf5",
    "error": "#e06c75",
    "success": "#7fd88f",
    "warning": "#f5a742",
    "text": "#eeeeee",
    "muted": "#808080",
    "background": "#0a0a0a",
    "panel": "#141414",
    "element": "#1e1e1e",
    "selection": "#282828",
    "border": "#484848",
    "borderSubtle": "#3c3c3c"
  }
}
```

Все цвета опциональны — недостающие берутся из темы по умолчанию. Активная тема сохраняется в базе; переменная окружения `TASKY_THEME` временно переопределяет её.

Значки слева в меню страниц (Задачи / Проекты / Отчёты / Настройки) — глифы Nerd Font. Для их корректного отображения терминал должен использовать патченый шрифт Nerd Font (например, `FiraCode Nerd Font`); без него вместо значков будут пустые или некорректные символы. Код легко переключить на буквы `T/P/R/S` — заменить глифы в `sidebarItems` (`internal/ui/app.go`).
